## 0. 结论

**一份 `core`；差异用「端口 + 适配器」隔离；平台优化只发生在最外层。**

判断标准：

> `core` 不应知道自己跑在哪个平台。出现 `runtime.GOOS`，说明这段逻辑放错层了。

复用比例：约 **80% 代码只写一次**（HTTP、解析、快照、周次计算、DTO、错误码、告警判定、用例编排、单测）；各端只写「触发器 + 呈现 + 平台能力」。

---

## 1. 哪些复用、哪些不复用

| 一份（`core` / `app`） | 各端各自实现 |
|---|---|
| CAS 登录、`Sync()`、快照编解码 | **谁触发**：进程调用 / ticker / 用户点击 |
| `Query(snapshot, date/week/range)` 纯计算 | **结果给谁**：stdout / 系统通知 / 屏幕 |
| 电费 `getbindroom` / `getusedetail` 请求与解析 | **存哪儿**：`0600` 文件 / DPAPI / Keystore |
| 校园网判态与登录/下线表单构造（纯函数） | **网络 I/O**：探测 302 与 POST 由 `internal/platform` 适配器执行 |
| 共享 DTO、统一错误码、快照版本 | **UI**：无 / 托盘 / Compose |
| 可用天数估算、告警去重判定 | **平台优化**：见 §5 |

所以「为平台单独优化」不是改核心，而是**同一组用例的不同组合方式**，外加一层平台适配器。

依赖方向恒向下：`core` 不 import `app`，`app` 不 import `cmd`，`core` 绝不 import `platform` 实现。

## 4. 端口

```go
// internal/core/ports.go —— 只定义，不实现
package core

type KVStore interface {
    Get(key string) ([]byte, error)
    Put(key string, v []byte) error // 实现方负责权限 / 加密 / 原子写
    Delete(key string) error
}

type HTTPDoer interface {
    Do(*http.Request) (*http.Response, error)
}

// 可选能力：CAS 跨主机登录需逐跳吸收 Cookie（M1 实测新增）。
type NoRedirectDoer interface {
    DoNoRedirect(*http.Request) (*http.Response, error)
}

type Clock interface {
    Now() time.Time
}

type Notifier interface {
    Notify(title, body string) error
}

// 校园网：自动模式只问「网络能不能用、要不要先恢复」。
type NetworkReady interface {
    EnsureCampusNetwork(ctx context.Context) error
}

// 校园网：Windows 手动模式与 Android 手动动作共用的原始操作。
// 纯函数（ParseProbe / 表单构造）留在 core/campusnet，I/O 由平台适配器实现。
type CampusNetwork interface {
    Status(ctx context.Context) (CampusStatus, error)
    Login(ctx context.Context) error
    Logout(ctx context.Context) error
    Relogin(ctx context.Context) error // 先判态：在线则下线 → 复探；未认证跳过下线；随后登录 → 复探确认
}
```

`CampusNetwork` 是为「手动登录 / 下线 / 重登」新增的端口，与 `NetworkReady` 并列；它不是 `NetworkReady` 的别名，后者是「自动恢复」的组合用例入口。本文的端口与用例清单以当前实现为准；`AGENTS.md` §3.1 的已知端口清单一致，§3.2 的用例清单尚未收录 `ExportTimetableCSV`（该文件由维护者维护，不在本 PR 修改）。

| 端口 | 隔离的差异 | 额外收益 |
|---|---|---|
| `KVStore` | `0600` 文件 / DPAPI / Keystore | 快照可用内存实现做单测 |
| `NoRedirectDoer` | CAS 跨主机逐跳重定向 | 手动吸收路径参数里的 Cookie，避免自动跟随丢会话 |
| `HTTPDoer` | 代理、TLS、强制 IPv4、超时 | `httptest` 可模拟「会话失效返回 200」、双层 JSON、业务错误码 |
| `Clock` | 时区 | 周次、学期边界、`inSemester`、告警去重可注入任意日期做单测 |
| `Notifier` | Windows 通知 / no-op | 告警判定纯函数化，不需要 build tag；Windows 实现是 `cmd/kemaolife-agent/ui.Tray.Notify`，其余平台用 `notify_stub.go` |
| `NetworkReady` | Portal / 802.1X / 客户端认证 | `core` 只放纯函数（`ParseProbe` 判 `Location`、构造表单）；探测 / 登录的 HTTP I/O 与自签证书策略锁在平台层，`core` 不持有网关地址与客户端 |
| `CampusNetwork` | 手动判态 / 登录 / 下线 / 重登（Windows + Android 共用） | 两个平台适配器实现同一组原语，`app` 用例不关心平台 |

> **强制 IPv4**：教务 CAS 域名解析出了 AAAA 记录，但 aic 服务器**没有 IPv6 监听**。默认双栈拨号会先试 IPv6，连不上只能等超时（约 10 秒）再回退 IPv4 —— 每次请求都白等 10 秒。
>
> 所以这里要的是**禁用 IPv6**，而不是「优选」：
>
> ```go
> // internal/platform httpdoer.go
> dialer := &net.Dialer{Timeout: 5 * time.Second}
> transport := &http.Transport{
>     DialContext: func(ctx context.Context, network, addr string) (net.Conn, error) {
>         return dialer.DialContext(ctx, "tcp4", addr) // 强制 IPv4
>     },
>     TLSHandshakeTimeout: 10 * time.Second,
> }
> ```
>
> 当前 `Deps.HTTP` 是教务与电费共用的单一 `HTTPDoer`，因此 `tcp4` 同时作用于两者；Portal 为独立平台适配器（M2 已实现，M4 复用），不在此客户端内。

## 5. 用例层：触发器留在外面

```go
func SyncTimetable(ctx context.Context, d Deps, cfg model.Config) (SyncResult, error)  // 含可选会话探活
func GetSchedule(ctx context.Context, d Deps, cfg model.Config, date model.Date, mode CacheOption) (ScheduleResult, error)
func GetWeekSchedule(ctx context.Context, d Deps, cfg model.Config, week int, mode CacheOption) (WeekResult, error)
func ExportTimetableCSV(ctx context.Context, d Deps, cfg model.Config) (ExportResult, error) // 只读快照导出 WakeUp 课程表 CSV（0 请求）
// CacheOption：RefreshFirst = 先刷新再计算（CLI）；CacheOnly = 只读本地快照、0 请求、stale 恒 false（Android）；刷新由独立 timetable.sync 承担
func CheckElectricity(ctx context.Context, d Deps, cfg model.Config, yearMonth string) (model.ElectricityReport, error) // 2 主请求 + 采集时刻请求；cfg 经 Config.ElectricityStudent() 取电费学号（electricityStudentId 空则回退学号）
func alert.Evaluate(prev alert.State, cur model.ElectricityStatus, now time.Time, cfg alert.Config) (alert.Decision, alert.State) // ★ 纯函数
func EnsureCampusNetwork(ctx context.Context, d CampusDeps) error                    // 仅 Windows 自动模式
func GetCampusNetworkStatus(ctx context.Context, d CampusDeps) (model.CampusStatus, error)
func LoginCampusNetwork(ctx context.Context, d CampusDeps) error
func LogoutCampusNetwork(ctx context.Context, d CampusDeps) error
func ReloginCampusNetwork(ctx context.Context, d CampusDeps) error
```

差异只体现在「谁来调、多久调、结果去哪、活多久」：

| | CLI（linux / darwin） | Windows 常驻 | Android |
|---|---|---|---|
| `GetSchedule` / `GetWeekSchedule` | 每次进程调用一次（默认当日 / 当周），`RefreshFirst`：**内部先刷新** | 不调 | 打开 / 切周（tab1），`CacheOnly`：**只读本地快照**（0 请求；打开先读缓存后尝试同步覆盖） |
| `SyncTimetable` | 显式 `sync`（只刷新不查询） | 不调 | 打开 App（含从后台回到前台：特殊自动，不受最小查询间隔约束）、切回课表 tab（按间隔）、手动刷新 / 设置页「测试」（不受节流）；成功后回读缓存覆盖界面 |
| `ExportTimetableCSV` | 不调 | 不调 | 课表页「导出课表」：`CacheOnly` 只读快照（0 请求），SAF 落盘 |
| `CheckElectricity` | 显式 `kemaolife electricity`（2 主请求 + 采集时刻请求） | 启动立即查一次，之后 ticker 默认 4 小时（可配，≥ 600s）；菜单可「立即查询电费」 | 冷启动联网 + 进入更多按间隔 + 手动刷新 |
| `alert.Evaluate` | 不调 | 电费成功后由 `agent.Engine` 调用 | 不调 |
| `EnsureCampusNetwork` | 不调 | **仅自动模式**每轮电费轮询前置（电费轮询开始前） | 不调 |
| `GetCampusNetworkStatus` 等 | 不调 | 启动立即判态一次，之后独立判态 ticker 默认 120s；托盘菜单可「立即探测校园网」；手动按钮用 `CampusNetwork` | tab2 / 手动动作前（「仅 WiFi 下探测」默认开；非 WiFi 不发 `campusnet.*` 请求） |
| 结果去向 | stdout（`--json` 只出数据） | 托盘右键状态 + 托盘悬浮提示 + Windows 通知 | Compose 三 tab |
| 进程生命 | 秒级 | 天级（开机登录自启一次，不保活） | 分钟级，随时被杀 |
| 平台优化 | 启动快、退出码清晰、无残留状态 | 连接池复用、内存保存告警态、电费轮询失败指数退避、静默时段、自动模式网络前置；判态轮询失败不退避 | 快照落应用私有目录长期复用、打开先读缓存 + 不受间隔约束的联网覆盖（其余自动按最小间隔节流）、被杀无副作用 |

CLI 不调用校园网用例（`000 §3.1`）。校园网用例用独立的 `app.CampusDeps`（`Clock` / `Net` / `Ready`），不挂在 `app.Deps` 下，因此 CLI 不需要为了「组装一致」而塞桩；`platform/campusnet_stub.go` 与 `notify_stub.go` 是备用实现（返回 `2001` / no-op），当前无装配点。

macOS 与 Linux 走同一组适配器（`HTTPDoer` / `FileStore` / `SingleFileStore` / `RealClock` / 桩）：差异只在 `config init` 关闭回显的 termios 实现（darwin 用 BSD `TIOCGETA/TIOCSETA`），以及后续 Windows 的加密存储；两平台都在「关闭失败」时由 `ReadSecret` 输出脱敏警告并继续读取，不引 Keychain，不改 `config show` 的 `configPath` 语义。

**课表查询 = 刷新 + 计算**：CLI 走 `RefreshFirst`，`GetSchedule` 内部先调 `SyncTimetable`，成功后用新快照计算；刷新失败则回落旧快照并置 `stale:true + syncedAt`（`docs/002 §1.3`）。所以 CLI 的「查询」不等于 0 请求 —— 刷新与查询是**同一个用例内的两步**。

**Android 走 `CacheOnly`**：查询只读本地快照、0 请求、`stale` 恒 `false`；联网刷新是另一个动作（`timetable.sync` / `SyncTimetable`，由打开 App、手动刷新、设置页对应功能域「测试」触发），成功后 UI 回读缓存覆盖界面（`docs/002 §5.3`）。打开 App 是特殊自动触发：首帧由 Kotlin 展示镜像与电费缓存渲染（0 请求、不等 `Init`），`Init` 后由 `CacheOnly` 回读 Go 快照校正，再同步课表并查询电费各一次，不受各自「最小查询间隔」（均默认 5 分钟、下限 1 分钟、上限 1440 分钟）约束；失败沿用旧缓存、置 UI 离线标记并保留 `syncedAt`，不阻塞展示、不改写信封 `stale`。切回课表 tab / 进入更多 tab 等非打开自动触发按各自最小查询间隔节流，从后台回到前台仍按「打开」处理，手动 `刷新` / `测试` 不受节流。两者共用同一份快照，不合并成一个用例的原因很直接：Android 切周如果走「查询即刷新」，就等于每次翻页都白打一次教务接口。

这些优化没有一个需要改 `core`：Android「不做后台」与 Windows「常驻」只是分别调用 `GetSchedule` 与 `CheckElectricity`，用的是同一个 `app` 包；告警判定走 `core/alert.Evaluate`，由 `internal/agent` 串在电费成功路径上。原生 UI 也不影响复用 —— 托盘与 Compose 都只消费 DTO。

`core/alert.Evaluate` 做成纯函数（旧状态 + 当前余额 + 当前时间 + 配置 → 是否提醒 + 新状态）尤其重要：只有 Windows 用它，但只写一份、只测一份。

## 6. Android 复用（唯一的真难点）

`gomobile bind -target=android -javapkg com.github.echoping07.kemaolife.bridge -o kemaolife.aar ./cmd/kemaolife-mobile` 产出 `.aar`，Go 只导出字符串函数；UI 用 Kotlin / Compose 原生写。Android applicationId / Kotlin 主包为 `com.github.echoping07.kemaolife`（全小写，与 module path 反向对应）。

- `core` / `app` 100% 复用，JNI 边界最窄：`gobind` 只允许导出字符串等受限类型，Go 侧只保留 `Init` / `Call` 两个字符串入口，DTO 不跨边界。
- 代价：需要 Android SDK/NDK；`x/mobile` 非官方正式支持。
- 已排除：Go 本地服务 + WebView（浏览器内核）、Kotlin 重写查询（周次算法漂移）、Gio 全 Go UI（违背三端差异定位）。

### 6.1 JSON 门面

`gobind` 对导出类型限制严格（结构体切片、跨 JNI 接口），**不把领域对象导出给 Kotlin**，边界只放一个路由函数：

```go
// cmd/kemaolife-mobile/bridge.go —— 唯一导出入口
package kemaolife

// Init 由 Kotlin 传入可写目录与解密后的凭据（不落盘、不进日志）。
func Init(configJSON string) string { /* ... */ }

// Call 请求 JSON 进，响应 JSON 出。
func Call(reqJSON string) string { /* ... */ }
```

请求（示例；`op` 基线以 [002 §2.1](002-功能规格.md#21-android-门面jni-边界) 为准）：

```json
{"op":"ping"}
{"op":"timetable.sync"}
{"op":"timetable.today"}
{"op":"timetable.week","week":<周次>}
{"op":"timetable.date","date":"<YYYY-MM-DD>"}
{"op":"timetable.probe"}
{"op":"timetable.export"}
{"op":"electricity.report","month":"<YYYY-MM>"}
{"op":"electricity.probe","month":"<YYYY-MM>"}
{"op":"campusnet.status"}
{"op":"campusnet.login"}
{"op":"campusnet.logout"}
{"op":"campusnet.relogin"}
{"op":"campusnet.probe"}
```

`timetable.today` / `timetable.week` / `timetable.date` 为 `CacheOnly`（0 请求、`stale` 恒 `false`），联网刷新只走 `timetable.sync`；`timetable.week` 的可选响应字段 `lastWeek`（缺省 `0` = 未知）供翻页容器确定边界。`timetable.export` 把本地快照的整学期课节导出为 WakeUp 课程表 CSV（同属 `CacheOnly`，0 请求），响应 `data` 为 `csv` / `filename` / `syncedAt` / `lessonCount`，格式与字段见 [002 §3.1.1](002-功能规格.md#311-课表导出现wakeup-课程表-csv)；`*.probe` 由设置页对应详情页的「测试」触发，响应 `data` 为 `ok` / `elapsedMs` / 脱敏摘要 / 白名单 `detail`（可带 `report` / `campusStatus`），UI 据此刷新。

统一信封（与 [002 §2](002-功能规格.md#2-json-信封) 同构，均为 Go 强类型 DTO 编解码）：

```json
{"ok":true,"data":{},"ts":"<响应时间>"}
{"ok":false,"error":{"code":3002,"message":"会话失效，需重新同步"},"ts":"<响应时间>"}
```

`error.code` 使用 002 §4 的 `1001`–`5001` 域；JSON 信封内不出现 CLI 退出码。

好处：Go 内部（CLI / Windows）直接用强类型 API，只有 JNI 边界付一次编解码；契约即一份 schema，CLI 的 `--json` 复用同一个 `model`，三端字段天然一致。D12 待定稿，实现时标 `TODO(D12)`。

### 6.2 平台能力

Go 访问不到 Android Keystore / 私有目录：

- Kotlin 启动时通过 `Init(configJSON)` 把「可写目录 + 解密后的凭据 + 设备时区」交给 Go；Go 用 `platform.NewFileStore(cacheDir)` 把快照留在应用私有目录，凭据只存在于进程内存。
- **加密与持久化留在 Kotlin，Go 只处理内存中的凭据。**设置页（tab3）由 Kotlin 直接写 Keystore，保存后重新 `Init(configJSON)`，门面不提供 `config.*` op。
- `Init(configJSON)` 传入 `cacheDir`、教务 / 电费 / 校园网凭据、设备时区与可选 `resetSnapshot`；字段表见 [002 §2.1](002-功能规格.md#21-android-门面jni-边界)。会话代次由 `generationStore` 守卫 `KVStore`：换账号后旧请求不能覆盖新会话快照；这不是新端口。
- `Clock` / `HTTPDoer` 用默认实现。非敏感偏好（`AppPreferences`）、主题色（`ThemePreferences`）、课表展示镜像（`TimetableCache`）、启动时序（`AppOpenGate` / `StartupTiming`）与横向翻页（`WeekPager`）都留在 Kotlin 呈现层，不重新实现业务计算。
- `CampusNetwork` 的 Android 适配器：`api-docs/003` 的探测地址是 **HTTP 明文**（https 拿不到 302），Android 9+ 默认禁明文 → 用 `network_security_config.xml` **只对该探测地址**放行 `cleartextTrafficPermitted`，不设全局 `android:usesCleartextTraffic`；Portal 域另配仅该域生效的信任锚点，自签证书跳过校验由 Go 侧 Portal 专用 HTTPS 客户端完成，不全局 `InsecureSkipVerify`。探测 302 下发的六参数只在内存构造表单，不落仓库 / 日志 / 错误信息 / 对外分享；`brasName` / `brasAddress` / `vlan` / `deviceIp` / `mac` 作为 `CampusStatus` 可选字段仅在本人设备「更多」页折叠展示，`distoken` 不进 DTO 或 UI。
- Portal 为内网地址；「仅 WiFi 下探测」默认开启时，非 WiFi 直接落 `offline` 且不发任何 `campusnet.*` 请求（status / probe / login / logout / relogin 一并不发）；UI 明示「需连接校园网 WiFi」，不误报为认证失败。

### 6.4 Windows 原生层与校园网认证

Windows 是**一个原生托盘程序**，不是浏览器套壳：按 D10 未定稿前的保守基线，用标准库 `syscall` 直调 user32 / gdi32 / shell32 与 `advapi32` / `crypt32` 实现托盘、菜单、设置窗口、通知、自启注册表项与 DPAPI，单二进制、免 .NET / WebView2 / 第三方依赖（`TODO(D10)`）。当前通知由托盘 `NIF_INFO` 承载，进程启动时设置 `Kemaolife.Agent` AUMID 用于归类；Windows 按版本呈现气泡 / toast 样式，不承诺 WinRT Toast 或操作中心归档，也不引入 COM / 快捷方式。

`kemaolife-agent.exe` 常驻。校园网默认**手动模式**，自动模式才做轮询前置：

```
自动模式：启动 → EnsureCampusNetwork() → CheckElectricity() → alert.Evaluate() → Notifier
手动模式：启动 → CheckElectricity() ───────────────────────────────────→ alert.Evaluate() → Notifier
                          │（前置认证失败只更新托盘状态，不阻断本轮电费，也不自动登录）
托盘右键：校园网状态 / 剩余电费（只读两行） + 按钮组 + 通用项
手动：登录校园网 | 下线 | 重登        自动：重登
通用（两种模式）：立即探测校园网 | 立即查询电费 | 设置… | 退出
```

要点：

- **开机自启 = 登录时启动一次**：设置窗口可开关（默认勾选）；**仅在设置保存时**写 HKCU `Run` 项，首次安装不写、不自动生效；不写守护进程、不注册服务、不保活、被用户退出或系统杀掉后不重启。启动时若无学号会直接打开设置窗口，首轮电费查询与首轮判态立即执行。
- `NetworkReady` 只暴露「确保网络可用」（自动模式）；手动动作走 `CampusNetwork` 端口；Portal 细节全在 `internal/platform/portal.go` 与 `portal_{windows,android,other}.go`。
- 凭据独立字段（D9 已定稿），DPAPI 加密，不明文落盘、不写日志；不复用教务密码。
- 当前按 `api-docs/003` 的固定探测地址判 302；`TODO(D11): 待定` —— 联网探测目标是否改为电费接口可达性仍未定稿，不在本次自行切换。
- 电费轮询**默认 4 小时（14400s）**，可自定义，低于 600s 钳制到 600s 并提示；电费查询连续失败按指数退避并更新托盘状态，不重复弹失败通知；退避上限 24 小时（`TODO(D3)`）。
- Windows 校园网判态另有独立周期：默认 120s、下限 30s（钳制并提示），启动立即探一次，失败归 `offline` 且不退避；菜单「立即探测校园网」只探一次、不登录。
- Android 的校园网是**全手动、无轮询前置**；已落地的 `internal/platform/portal.go` + `portal_android.go` 复用同一组纯函数与 `CampusNetwork` 端口，不新建进程、不后台常驻。

本地自检（与 `CONTRIBUTING.md` / PR 模板一致；CI 见 `.github/workflows/ci.yml`）：

```bash
gofmt -l .

# core 不得依赖平台/UI 包

# CLI 与桌面 / 移动端交叉编译
```

**Release 产物（0.4.1 起）**：`release.yml` 按**五类**出 12 个包 + `SHA256SUMS`（由 10 行变 12 行，以上十二个包的校验和）——Linux CLI 三个 tar.gz（`kemaolife_<版本>_linux_{amd64,arm64,armv7}.tar.gz`）、macOS CLI 两个 tar.gz（`kemaolife_<版本>_darwin_amd64.tar.gz` 对应 Intel Mac / x86_64、`kemaolife_<版本>_darwin_arm64.tar.gz` 对应 Apple Silicon / M1 及以后，包内含 `kemaolife` / `LICENSE` / `INSTALL.txt`，与 Linux 包同构；`darwin` 即 macOS，与 `GOOS=darwin` 口径一致）、Windows 托盘两个 zip、Android 四 ABI 四个 APK、agent skill 一个 zip；即 Linux CLI / macOS CLI / Windows 托盘 / Android 四 ABI APK / agent skill 五类，其余包不变。

macOS 二进制由 Linux CI 交叉编译，**未经 Apple Developer ID 签名、未经 Apple 公证（notarization）**：无 Apple 付费账号证书，不做公证；arm64 二进制带 Go 链接器自动生成的 ad-hoc 代码签名（Apple Silicon 要求），**这不等于 Apple 签名**。浏览器下载解压后二进制可能带 `com.apple.quarantine`，首次运行被 Gatekeeper 拦截，需手动 `xattr -d com.apple.quarantine <解压后的 kemaolife>`（或 `xattr -r -d com.apple.quarantine <目录>`）后再运行。仍不做 Developer ID 签名 / 公证 / Keychain / 第三方依赖；凭据与缓存仍是 `~/.config/kemaolife/config.json`（目录 `0700` / 文件 `0600` / 原子写，XDG 优先）与 `~/.cache/kemaolife/`。0.4.1 发布当时未改任何对外契约：CLI 命令 / 参数 / 退出码 0/1/2/3/4、JSON 信封、DTO、错误码 1001–5001、Android 门面 `op`、快照 `Version` 均不变；此后新增的 `timetable.export` / `*.probe` 与可选字段见 §5、§6.1 及 [002 §2.1](002-功能规格.md#21-android-门面jni-边界)。
