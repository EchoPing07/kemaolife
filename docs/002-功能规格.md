## 1. CLI（linux / darwin，供 agent）

### 1.1 命令集

```bash
kemaolife --version                             # 版本号（源码常量，不联网）
kemaolife --help                                # 帮助
kemaolife help <command>                        # 子命令帮助

kemaolife config init                           # 交互录入学号 + 教务密码（0600）
kemaolife config set customercode <学校代码>     # 覆盖学校代码内置默认值（默认 3126）
kemaolife config show                           # 展示配置状态；学号与密码恒脱敏

kemaolife timetable                             # 默认当日
kemaolife timetable sync                        # 登录并刷新快照（1 登录 + 2 请求）
kemaolife timetable today                       # 当日
kemaolife timetable week [N]                    # 省略 N = 当周；N = 指定周
kemaolife timetable date <YYYY-MM-DD>           # 指定日期

kemaolife electricity [--month YYYY-MM]         # 一次返回剩余电费 + 每日用量（2 主请求 + 1 采集时刻请求）
```

版本号取自 `internal/version.Version`（仓库唯一来源，三端共用，改版本只改这一行），不由构建参数覆盖；`commit` 仍由编译期 `-ldflags "-X main.commit=<提交号>"` 注入。`--version` 不联网、不读配置；带 `--json` 时走 §2 信封，`data` 为 `{"version":"<版本号>","commit":"<提交号>"}`，否则输出一行纯文本。`--help` / `help` 输出纯文本帮助，不进信封。源码常量是待发布版本，正式发版在变更合并到 `main` 后打 `vX.Y.Z` tag，tag 与常量一致才算发布。

**配置分域**

| 域 | 字段 | 来源 |
|---|---|---|
| 教务 | 学号、教务密码 | `config init` 交互录入；默认关闭回显（无法关闭时 `stderr` 明确警告并继续读取，输入可能被看到）、不进命令行参数、不写日志 |
| 电费 | 学号（复用教务）、学校代码 `customercode` | 学校代码有**内置默认值**，支持自定义覆盖；**电费接口无密码**（`api-docs/002` §1 无鉴权） |
| 校园网 | 不存 | CLI 无校园网功能 |

学校代码默认值：**3126**（学校事实，非个人隐私），写在 `cmd` 层并支持 `-ldflags -X main.defaultCustomerCode=...` 覆盖；用户可 `config set customercode <学校代码>` 再覆盖。**禁止**写成 `internal/core` 包级常量或对外发布的通用常量。`config show` 用 `customerCodeSource: "default" | "custom" | "missing"` 标注来源；`missing` 仅在默认值与用户配置都为空时出现。

`config show` 输出（示例值为占位符）：

```json
{
  "studentId": "****",
  "eduPassword": "****",
  "customerCode": "****",
  "customerCodeSource": "default",
  "configPath": "<用户主目录>/.config/kemaolife/config.json"
}
```

**能力状态**（与 [000 §4](000-需求与产品定位.md#4-功能矩阵) 一致）

| 能力 | 状态 |
|---|---|
| `--version` / `--help` / `help`、`config.*`、`timetable [sync/today/week/date]`、`electricity` | M1 必做 |
| 校园网状态查询 | **不做**（CLI 无此功能） |
| `timetable range` | **不做**（`QueryRange` 仅作 `core` 内部纯函数，用于当周 7 日查询，不暴露为命令） |

全局参数：

| 参数 | 语义 |
|---|---|
| `--json` | `stdout` 只输出 §2 信封；诊断信息全部走 `stderr` |
| `--config <path>` | 指定配置文件（默认 `~/.config/kemaolife/config.json`；有 `XDG_CONFIG_HOME` 时优先用之；macOS 同口径，`config show` 的 `configPath` 语义不变） |
| `--timeout <dur>` | 单次网络超时上限（默认 30s；也接受纯秒数） |
| `--verbose` | 诊断文本输出到 `stderr`（如启动提示与超时上限；不含个人信息、不承诺错误类别 / 耗时 / 状态码） |

全局参数可放在子命令之前或之后；支持 `--flag=value`、`-h` / `-v` 别名与 `--` 终止符。`--` 可放在第一个子命令之前或其参数之后：终止符之后的内容按子命令原样参数处理；`-v` / `--version` 在子命令之前或之后均可生效，子命令之后同样可用 `--json` / `--verbose` / `--config` / `--timeout` / `-h` / `--help`。

约定：

- 无 `--json` 时输出人类可读表格或单行状态文本，字段与 JSON 同源；允许额外的「数据时间 / 配置引导 / 权限」提示行，不输出 DTO 之外的业务数据。`--json` 时 `stdout` 恒只有信封（交互提示一律走 `stderr`）。
- agent 侧固定带 `--json`，只读 `stdout`。
- `kemaolife timetable` 无子命令等价于 `kemaolife timetable today`。
- **查询类子命令（`timetable` / `today` / `week` / `date`）每次都会先尝试联网刷新快照**，成功则用最新数据（`stale:false`）；刷新失败（网络不可用 / 会话失效）时沿用旧快照，信封带 `stale:true` 与 `syncedAt`，查询照常返回、退出码仍为 `0`。`sync` 只做刷新、不查询。
- `kemaolife electricity` 一次调用内部发 2 个主请求（`getbindroom` + `getusedetail`），任一失败整体报错、不返回半份数据；两个主请求成功后还会发 1 个 `getstuindexpage` 取 `collecdate`（真实采集时刻），该请求失败或缺失时静默降级到 `opdtdate`（数据截止日），不影响整体成功。`--month` 省略时取当月。
- 周次从 `1` 起；`week` 越界时返回 `inSemester:false` 而非报错。
- 明确：`timetable`（默认当日）/ `today` / `week [N]` / `date` 指向非学期内日期时，一律返回**成功信封**（`ok:true`、退出码 `0`），由 `data.inSemester:false` + `entries:[]` 标记；不产生 `error`、不触发 `1002`。`timetable week` 省略 N 且当前日期不在学期内时同样按成功返回（7 天全部 `inSemester:false`），不猜周次、不报错。与 R1「非学期内明确标记」、§3.1 DTO 及 [api-docs/001-timetable §8](../api-docs/001-timetable/README.md#8-待验证) 同口径。区段查询不作为命令暴露（`QueryRange` 仅供 `core` 内部当周 7 日计算）。

### 1.2 退出码

| 码 | 含义 | agent 应对 |
|---|---|---|
| `0` | 成功 | — |
| `1` | 业务失败（接口返回业务错误码等；`inSemester:false` 不属此类） | 读 `error.message` 说明原因 |
| `2` | 参数错误 | 修正命令后再试，不要重试 |
| `3` | 凭据缺失 / 会话失效 | 引导 `kemaolife config init` 或 `kemaolife timetable sync` |
| `4` | 网络或接口不可用 | 课表刷新失败会自动回落旧快照（信封 `stale:true`）；仅当**连旧快照都没有**时才以 `4` 退出。电费失败按 §4 错误码映射（可为 `1` / `3` / `4`），不使用缓存 |

### 1.3 刷新与降级

**查询类子命令每次都先刷新快照**（`timetable` / `today` / `week` / `date`），刷新失败则回落旧快照。

| 场景 | 行为 |
|---|---|
| 课表查询 · 刷新成功 | 用最新快照返回，`stale:false`，`syncedAt` 为本次同步时间 |
| 课表查询 · 刷新失败但有旧快照 | 沿用旧快照返回，**`stale:true` + `syncedAt`（旧快照的同步时间）**，退出码仍 `0`；不重复报 `3002` |
| 课表查询 · 刷新失败且无旧快照 | 退出码 `4`（`4001`，网络不可用）/ `3`（`3001`/`3002`/`3003`，凭据 / 会话 / 快照问题） |
| 课表查询 · 会话失效 | 刷新内部自动重登一次；仍失败则按上一行处理（有旧快照就 `stale:true` 返回） |
| 课表查询 · 非学期内日期 | 成功信封 + `data.inSemester:false`，退出码 `0`（与刷新成败无关） |
| `timetable sync` | 只刷新不查询；失败直接报错（不回落），退出码按错误码映射 |
| 电费查询 | 2 个主请求 + 1 个采集时刻请求；主请求失败按 §4 映射退出码，采集时刻请求失败静默降级；不使用缓存冒充新数据 |

要点：

1. **刷新失败不阻塞查询**：断网时课表照常可查，但必须让 agent 看到 `stale:true`，以便向用户说明「数据时间」。
2. **刷新失败不等于命令失败**：只要还有旧快照，退出码就是 `0`；`stale` 是唯一「旧数据」标记。
3. **无旧快照时才失败**：这是唯一需要用户先手动 `sync` 的场景（首次使用 / 快照被清）。缺教务凭据但有旧快照时仍按 `stale:true` 返回，退出码 `0`。
4. `sync` 与查询不合并：`sync` 用于「只想刷新、不要结果」，也是首次使用的引导步骤。

Android 打开 App 时由 UI 层并行触发 `timetable.sync`，与 `timetable.today` 是两个独立动作，见 §5.3。

## 2. JSON 信封

CLI `--json` 与 Android 门面共用同一信封，字段名一致。

成功：

```json
{
  "ok": true,
  "data": {},
  "ts": "<响应时间>",
  "stale": false,
  "syncedAt": "<快照同步时间>"
}
```

失败（CLI `--json` 与 Android 门面同构）：

```json
{
  "ok": false,
  "error": {"code": 3002, "message": "会话失效，需重新同步"},
  "ts": "<响应时间>"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `ok` | bool | 是否成功 |
| `data` | object | 业务数据，`ok:false` 时缺省 |
| `error` | object | `{code, message}`，`ok:false` 时存在 |
| `ts` | string | 响应生成时间（RFC3339，本地时区） |
| `stale` | bool | 课表查询恒给出；刷新成功为 `false`，刷新失败沿用旧快照时为 `true`。非课表命令可缺省 |
| `syncedAt` | string | 快照同步时间；课表查询恒给出（刷新成功时是本次时间，`stale:true` 时是旧快照时间）；CLI 与 Android 的 `timetable sync` 也给出 |

`error.code` 使用 §4 的 `1001`–`5001` 域；CLI 退出码 `0/1/2/3/4` 由该域映射得出（§4），**JSON 信封内不出现退出码**。`ok:false` 时 `data` 缺省，`ok:true` 时 `error` 缺省。所有示例按 Go 强类型 DTO 编解码；`curl` 与 JSON 报文块仅作协议证据。

## 3. 数据结构

### 3.1 课表

§3 定义三端共享 DTO；CLI 各子命令的 `data` 结构如下（字段名稳定，新增字段必须可选）：

| 命令 | `data` 结构 |
|---|---|
| `timetable` / `today` / `date` | `DaySchedule`（本节） |
| `timetable week [N]` | `{ "week": <int>, "days": [<DaySchedule> × 7] }` |
| `timetable sync` | `{ "syncedAt", "week1Monday", "lastWeek", "lessonCount" }`（不含 Cookie） |
| `electricity` | `ElectricityReport`（§3.2） |
| `config init` | `{ "studentId": "****", "eduPassword": "****", "configPath" }` |
| `config set customercode` | `{ "customerCode": "****", "customerCodeSource" }` |
| `config show` | `{ "studentId", "eduPassword", "customerCode", "customerCodeSource", "configPath" }` |
| `--version --json` | `{ "version", "commit" }` |

Windows 端不暴露 CLI / JSON 信封，托盘菜单、悬浮提示与设置窗口只消费本机状态与 DTO，不新增对外字段。

示例为字段示意；`<...>` 是占位符字符串，实际数值字段按字段表编码。

```json
{
  "date": "<YYYY-MM-DD>",
  "week": "<周次>",
  "weekday": "<1-7>",
  "weekdayCn": "<一/二/…/日>",
  "inSemester": true,
  "entries": [
    {
      "name": "<课程名>",
      "periods": "<起始小节>-<结束小节>",
      "time": "<上课时间>",
      "teacher": "<教师>",
      "location": "<地点>",
      "weeksText": "<周次文本>"
    }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `date` | `YYYY-MM-DD` |
| `week` | 周次，从 1 起 |
| `weekday` | 周一 = 1 … 周日 = 7 |
| `weekdayCn` | 一 / 二 / … / 日 |
| `inSemester` | 是否在本学期范围 |
| `entries[]` | 当天课节；空数组 = 当天没课 |

`entries[]` 按 `periods` 起始节次升序；同一节次多门课按课程名排序，保证输出稳定可 diff。

快照结构：

| 字段 | 说明 |
|---|---|
| `version` | 快照格式版本，当前 `1`；版本不匹配即丢弃重拉 |
| `syncedAt` | 同步时间 |
| `week1Monday` | 第 1 周周一（日期锚点） |
| `week1Dates` | 第 1 周 7 个日期 |
| `slotTimes` | 6 个大节时间，如 `08:30~10:00` |
| `lastWeek` | 由课程推断的学期最后一周 |
| `lessons` | 展开后的课节（`weeks` 为数组） |
| `cookies` | 会话 Cookie，**敏感**，加密或 `0600` 存储 |

### 3.2 电费

`kemaolife electricity` 与 `electricity.report` 统一返回 **`ElectricityReport`**（新增外层 DTO）；内嵌两个既有 DTO，**内部字段名不变**：

示例为字段示意；`<...>` 是占位符字符串，实际数值字段按字段表编码（数值或 `null`）。

```json
{
  "status": {
    "roomName": "<校区>_<楼栋>_<楼层>_<房间>",
    "roomVerify": "已脱敏",
    "balance": "<剩余量>",
    "unit": "度",
    "businessType": 0,
    "meterStatus": "<状态>",
    "collectedAt": "<采集时间>",
    "dailyAvg": "<近七日均量或 null>",
    "estimatedDays": "<估算天数或 null>"
  },
  "usage": {
    "yearMonth": "<YYYY-MM>",
    "monthUse": "<当月累计>",
    "dataUntil": "<YYYY-MM-DD>",
    "days": [
      {"date": "<YYYY-MM-DD>", "use": "<当日用量>"}
    ]
  }
}
```

`status`（`ElectricityStatus`）：

| 字段 | 说明 |
|---|---|
| `balance` | 剩余量（度） |
| `unit` | `度` / `吨` |
| `businessType` | `0` 电，`1` 水 |
| `collectedAt` | 数据采集时间；电表约 1 天延迟。CLI 输出 / 告警通知 / Android 电费页展示时必须写明「数据截至」，Windows 托盘不展示（§5.2） |
| `dailyAvg` | 取 `days[]` 最后 7 条的均值；无数据时为 `null`，不足 7 日按实际天数计算；均量 ≤ 0 时为 `0`（`estimatedDays` 为 `null`） |
| `estimatedDays` | `floor(balance / dailyAvg)`；`dailyAvg` 为 `null` 或 ≤ 0 时为 `null` |

`usage`（`ElectricityUsage`）：`yearMonth`、`monthUse`、`dataUntil`、`days[]`。`days[]` 按日期**升序**输出（`core` 显式排序，不依赖上游返回顺序）。

约定：`status` 与 `usage` 分别来自 `getbindroom` / `getusedetail` 两个主请求，**任一失败整体返回错误信封，不返回半份数据**；`collectedAt` 优先取 `getstuindexpage.collecdate`，失败或缺失时降级到 `getusedetail.opdtdate`。展示口径：CLI 人类可读输出、告警通知正文、Android 电费页必须标注「数据截至 `<collectedAt>`」；Windows 托盘菜单与悬浮提示按 §5.2 **不展示**「数据截至」，只展示当前值。快照结构未变，`version` 不升级。`roomName` 是本人宿舍标识，允许在本机 CLI 输出，但不进日志 / 错误信息 / agent 复述；`roomVerify` 恒脱敏。

### 3.3 校园网

```json
{
  "state": "online",
  "errorMsg": "<已知安全提示，可为空>",
  "checkedAt": "<检查时间>"
}
```

`state`：`online`（已在线）｜`unauth`（未认证）｜`offline`（不在校园网 / 探测失败）。

- 该 DTO 供 **Windows 托盘**与 **Android「更多」页**使用；**CLI 不暴露**。Windows 适配器的 `Status` 只返回 `state` 与 `errorMsg`，`checkedAt` 由 `app.GetCampusNetworkStatus` 用注入的 `Clock` 补齐；托盘 UI 本身不展示该时刻。`errorMsg` 来自上游 `Location`，必须经已知安全短语白名单过滤后才进入 DTO，未命中时置空（P2）。
- 探测失败（超时 / 非 302 / 无 `Location`）返回 `ok:true` + `state:"offline"`，**不是错误**；`campusnet.login` / `logout` / `relogin` 在 `offline` 态调用返回 `4001`。Windows 托盘手动动作绕过门面直接调 `app` 用例，仍按同一语义处理。
- 「下线」为统一术语（`api-docs/003`），不写「登出」；「重登」= 先探测判态，若已在线则下线并复探（约 2~3s 生效等待），若原本未认证则跳过下线；随后登录并复探确认。该路径避免未认证态下发无意义的下线请求，`distoken` 仍由每次下线前的探测现取。

## 4. 错误码

`error.code` 与 CLI 退出码同域，便于 agent 直接判断。

| code | CLI 码 | 含义 |
|---|---|---|
| `0` | 0 | 成功（仅内部枚举；成功信封不出现 `error`，故 `code:0` 不出现在 JSON 中） |
| `1001` | 1 | 业务失败（上游 `body.result != "0"`；参数缺失 / 学号无效细分见下） |
| `1002` | 1 | 不在本学期范围（保留码位；常规越界查询按 `data.inSemester:false` 返回成功，不产生本码） |
| `2001` | 2 | 参数错误 |
| `3001` | 3 | 凭据缺失 |
| `3002` | 3 | 会话失效，需重新同步 |
| `3003` | 3 | 快照缺失或版本不匹配 |
| `4001` | 4 | 网络不可达 / 超时（含 `offline` 态调用校园网动作） |
| `4002` | 4 | 响应格式异常（含双层 JSON 解析失败） |
| `4003` | 4 | 上游拒绝（认证失败、账号或密码错误） |
| `5001` | 1 | 未绑定房间（电费） |

细分口径：`body.result = -20003` / `-1`（必填参数缺失或学号无效）按 `3001`（凭据 / 配置问题，退出码 3）；外层 `result_ != "true"` 按 `code_` 与脱敏后的文案映射为 `3001`（配置可自行修正）或 `4001`（上游未开通 / 网络不可用）。上游文案一律脱敏后才进入 `error.message`，不得原样透传。

| 不做 | GUI、常驻、定时提醒、系统通知、区段查询、校园网状态查询；仍不做 Developer ID 签名 / 公证 / Keychain / 第三方依赖、不宣称 macOS 已实机验证 |

## 6. 告警规则（Windows）

`alert.Evaluate(prev, cur, now, cfg) → (Decision, alert.State)` 为纯函数；本节规则承接 §5.2 的 Windows 电费轮询链路。

**输入**：上一次状态、当前电费、由 `Clock` 注入的当前时间、配置（阈值、可用天数阈值、静默时段）。轮询间隔属于 `Engine.Run` 的触发周期，不参与纯函数判定。D4 已定稿为「系统通知为主、托盘状态为辅」；当前实现是 `ui.Tray.Notify` 调 `Shell_NotifyIcon(NIF_INFO)`，进程 AUMID 仅用于让通知归到 `Kemaolife.Agent`，具体呈现由 Windows 版本决定。

**规则**

1. **阈值**：`balance <= threshold` 或 `estimatedDays <= daysThreshold` 触发提醒。
2. **去重**：余额阈值与可用天数阈值各用独立标记；同一触发原因只提醒一次，余额回升到阈值以上（充值）后重置余额标记，可用天数高于阈值后重置天数标记。
3. **静默时段**：处于静默时段内不发送通知、也不置位告警标记（本轮余额与用量仍照常计算），退出静默后若仍满足条件则补发一次。
4. **数据时间**：通知正文必须包含「数据截至 `<collectedAt>`」。
5. **失败不告警**：电费查询失败（网络 / 凭据 / 业务错误）不触发余额提醒，只更新托盘状态；自动模式前置认证失败同样只记到托盘状态，但**不阻断**本轮电费查询与余额提醒（两者是独立链路）；手动校园网动作失败也不弹失败通知。
6. **退避**：电费成功路径按轮询间隔执行；连续电费查询失败时按指数退避重试，间隔从轮询间隔起步且逐步增大（不得比成功路径更频繁），不重复弹出失败通知。校园网判态轮询失败归 `offline`，不退避。退避上限数值待 D3 定稿，实现取 24 小时（大于轮询间隔）的保守值并标 `TODO(D3)`。

默认值：

| 项 | 默认 | 状态 |
|---|---|---|
| 轮询间隔 | **4 小时（14400s）** | 已定稿；可自定义，≥ 600s 硬下限，低于则钳制 |
| 余额阈值 | 10 度 | 可配置 |
| 可用天数阈值 | 3 天 | 可配置 |
| 静默时段 | 23:00–07:00 | 可配置 |
| 失败退避 | 起点 = 轮询间隔，指数增长 | 上限待 D3 定稿 |

## 7. Agent skill 要求（CLI）

`skills/kemaolife/SKILL.md` 必须写明（承接 §5.1；D2 待定稿，标 `TODO(D2)`）：

1. **触发场景**：今天有什么课 / 第 N 周课表 / 某天有没有课 / 电费还剩多少 / 版本与帮助。**不含**「能不能上网」——CLI 无校园网能力。
2. **命令速查**：`kemaolife` 前缀、子命令含义、`timetable` 默认当日、`electricity` 一条命令同时给余额与用量、周次与 `weekdayCn` 口径、`periods` 与 `time` 的含义。
3. **输出解读**：`entries: []` 表示当天没课；`balance` 单位度；`collectedAt` 是采集时间不是实时值、`dataUntil` 是数据截止日；`days[]` 按日期升序；**`stale:true` 表示本次刷新失败、用的是旧快照，必须向用户说明数据时间（`syncedAt`）**。当周不可解析时 `week` 省略 N 返回 7 天 `inSemester:false` 的成功结果，不产生 `1002`。
4. **失败处理**：`3` → 引导 `config init`，或首次使用先 `timetable sync`；`4` → 课表通常已自动回落旧快照（看 `stale`），电费明确报错、不得用缓存冒充新数据；`1` → 读脱敏后的 `error.message`；`2` → 修正命令、不重试。电费失败退出码按错误码可为 `1` / `3` / `4`。
5. **隐私约束**：默认关闭回显，无法关闭时明确告知「输入可能被看到」再读取；不复述密码、学号 / 学校代码；不把姓名、宿舍号、`roomVerify` 拼进回复或日志；不代查他人；`config show` 中学号恒 `****`。
6. **固定用法**：所有命令带 `--json`，只解析 `stdout`。
