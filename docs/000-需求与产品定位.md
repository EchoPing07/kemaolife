## 0. 一页概览

**一句话**：一套校园生活工具，围绕**课表、宿舍电费、校园网认证**三件事，按平台特性裁成三个形态，共用一份 Go 核心。

| 维度 | 结论 |
|---|---|
| 功能域 | **3 个**：课表查询、电费查询、校园网认证 |
| 端 | **3 个**：CLI（给 agent，支持 linux / darwin，windows 后续计划）、Windows（托盘常驻，给人）、Android（App，给人）。CLI 与桌面端是不同形态，同一台 Windows 机器上可以同时存在 CLI 与托盘程序，功能集与配置存储互不相干 |
| 命名 | Go module `github.com/EchoPing07/kemaolife`；三端标识围绕 `kemaolife` 派生（D1 已定稿，见 [002 §0](002-功能规格.md#0-命名基线d1-已定稿)） |
| 复用 | 一份 Go `core` + 端口适配器；平台只写触发器、呈现、平台能力 |
| UI | Windows / Android **原生 UI**，三端一律不用浏览器内核 |
| 隐私 | 只查本人数据；姓名、宿舍号、凭据、快照 cookies 不落日志、不外传 |

## 1. 需求基线

每条需求给出「背景 → 要求 → 验收」，后续设计以此为准，不再追溯讨论过程。

### R1 · 课表查询

**背景**：学生每天要确认上什么课、在哪上；教务系统网页在手机上难用，且每次查询依赖网络。

**要求**

1. 支持按**当日**、**当周**、**指定周**、**指定日期**四种维度查询。
2. **CLI 查询 = 先联网刷新 + 纯本地计算**：查询动作 = 同步一次（1 登录 + 2 请求）+ 纯本地计算（`RefreshFirst`）；同步成功即返回最新数据（`stale:false`）。同步失败时沿用旧快照并标 `stale:true` + `syncedAt`，不阻塞查询、不当作新数据。Android 查询（`timetable.today` / `timetable.week` / `timetable.date`）走 `CacheOnly`：纯读本地缓存、0 请求、信封 `stale` 恒 `false`；联网刷新是独立的 `timetable.sync` op。
3. 离线可用：断网时沿用旧快照仍能查整学期课表（CLI 标 `stale:true`，必须向用户说明 `syncedAt`）；Android 查询为 0 请求纯读缓存，打开 App 时同步失败则沿用旧缓存、置 UI 离线标记并保留 `syncedAt`，不阻塞展示、不改写信封 `stale`。
4. 结果字段稳定：日期、周次、星期、节次、时间、课程名、教师、地点、周次文本，非学期内明确标记。

**验收**：CLI 连网时每次查询都拿到最新课表（`stale:false`）；飞行模式下仍能查到本学期任意一天的课表且刷新失败标 `stale:true` + `syncedAt`；Android 查询（`timetable.today` / `week` / `date`）纯读缓存、0 请求、`stale` 恒 `false`，切周只读本地缓存（0 网络请求）；打开 App 先显示缓存课表与缓存电费（0 请求），再发起一次 `timetable.sync` 与一次电费查询（不受「最小查询间隔」约束，仍受就绪 / 凭据 / 在途请求门控），成功立即覆盖界面、失败沿用旧缓存并将课表置 UI 离线标记，不阻塞展示、不改写信封 `stale`；切回课表 tab / 进入更多 tab 等非打开自动触发按各自「最小查询间隔」节流；从后台回到前台仍算打开；`刷新` / `测试` 等手动查询不受节流；`inSemester` 判定与教务系统周次一致。

### R2 · 电费查询

**背景**：宿舍电费余额不透明，欠费断电前没有提醒；充值后也不知道到账没有。

**要求**

1. 一次查询同时返回剩余电量、宿舍标识、数据采集时间与每日用量，用于估算「还能撑几天」。
2. CLI 与 Android 用一条命令 / 一个 `op` 同时取余额与用量，两个请求任一失败整体报错，不返回半份数据。
3. Windows 端支持电费定时轮询（默认 4 小时，可自定义，≥ 600s 硬下限）+ 独立校园网判态轮询（默认 120 秒，≥ 30s 下限）+ 阈值提醒（同一阈值只提醒一次，充值后重置）。
4. 查询结果必须带**数据截止时间**（电表约有 1 天延迟，不能当实时值）：CLI 人类可读输出、告警通知正文、Android 电费页必须标注「数据截至」；Windows 托盘两处 UI 只给当前值，不展示采集时刻（见 [002 §5.2](002-功能规格.md#52-windows-托盘常驻主动说)）。
5. 只查本人数据，不支持、不实现他人或多账号批量查询。

**验收**：`balance` 返回的剩余电量与 H5 页面一致；余额跌破阈值时 Windows 只弹一次通知。

### R3 · 校园网认证

**背景**：校园网掉线后需要手动打开 Portal 页面重新认证；常驻程序在自动模式下可作为轮询前置恢复网络，手动模式下则把控制权交给人。

**要求**

1. 能判断当前是「已在线 / 未认证 / 不在校园网」三种状态。
2. Windows 提供**手动 / 自动二选一，默认手动**：手动模式由托盘按钮执行登录 / 下线 / 重登；自动模式未认证时自动登录、已在线不重复认证，并作为电费轮询前置；自动模式仍保留「重登」按钮。两种模式都支持只读的「立即探测校园网」。
3. Android 在「更多」页展示状态并支持**全手动**登录 / 下线 / 重登，不做后台、不轮询前置。
4. CLI 不提供校园网状态查询，也不保存校园网凭据。
5. 电费查询失败要退避重试，不重复弹失败通知；凭据独立存储、不复用教务密码、明文不落盘、不进日志。凭据独立字段已定稿（D9）。

**验收**：Windows 自动模式下开机未认证时自动恢复网络并完成一次电费检测；手动模式下不触发任何自动登录；Android 蜂窝数据下判「不在校园网」且不误报失败。

### R4 · 一份核心，三端复用

**背景**：三端功能集不同，但数据获取、解析、周次计算、DTO、错误码、告警判定完全相同；各写一套必然版本漂移。

**要求**

1. 单仓库、单 `go.mod`、多 `cmd`。
2. `core` 不知道自己运行在哪个平台：出现 `runtime.GOOS` 即视为分层错误。
3. 平台差异只能通过端口接口（存储 / HTTP / 时钟 / 通知 / 网络就绪）注入。
4. 周次计算、阈值判定等关键逻辑必须是可注入时钟的纯函数，并有单测。

**验收**：`go test ./...` 在三端同源通过；`internal/core` 不依赖任何平台包。

### R5 · 隐私与合规

**要求**

1. 电费接口**无鉴权**（IDOR），只允许查询本人数据；不批量遍历、不服务化、不售卖查询。
2. 真实姓名、楼栋房间号、用电作息、学号、密码、会话 cookies 一律不写日志、不进 agent 回复、不进仓库。
3. 凭据存储：CLI（linux / darwin）目录 `0700` / 文件 `0600`（原子写），Windows 用户级加密（DPAPI 或等价物），Android Keystore。
4. 个人隐私（学号、教务密码、Cookie、会话值、姓名、宿舍房间号、`roomverify`）一律用占位符（`<学号>`、`<密码>`、`<roomverify>`、`<校区>_<楼栋>_<楼层>_<房间>`）。学校代码（本项目内置默认 `3126`）与 Portal / 探测 IP 属学校与协议事实，可入仓；学校代码可内置默认并支持覆盖，但不得写成 `internal/core` 包级常量。

**验收**：仓库全文检索无真实学号 / 姓名 / 房间号 / 内网 IP / MAC；日志样本中无上述字段。

## 2. 功能域边界

### 2.1 课表

| 项 | 内容 |
|---|---|
| 数据来源 | 教务系统：CAS 登录 → 周锚点 + 课程 JSON → 本地计算 |
| 成本 | CLI 每次查询（`RefreshFirst`）= 1 次登录 + 2 个数据请求（快照会话有效时省掉登录，实测约 190ms~2s）；Android 查询（`CacheOnly`）0 请求，联网只由 `timetable.sync` 发起 |
| 缓存 | 快照可长期复用；含 cookies，属敏感文件 |
| 不做 | 选课、成绩、考试安排、调课提醒 |

### 2.2 电费

| 项 | 内容 |
|---|---|
| 数据来源 | 智能水电 H5 后端 `SWAEServlet`，表单 POST，双层 JSON |
| 成本 | 一次完整查询 2 个主请求（`getbindroom` + `getusedetail`）+ 1 个 `getstuindexpage` 取采集时刻（失败静默降级到 `opdtdate`）；对外表现为一条命令 / 一个 `op` |
| 数据特性 | 电表约 1 天延迟；Windows 托盘电费轮询 ≥ 600 秒/次 |
| 不做 | 代充值、他人查询、多账号、实时功率 |

### 2.3 校园网认证

| 项 | 内容 |
|---|---|
| 数据来源 | Portal（自签证书）+ 探测地址 302 重定向参数 |
| 成本 | 探测 1 请求 + 登录 1 请求；约 2~3 秒后复探确认 |
| 数据特性 | HTTP 恒 200，成败只看 body 的 `success`；重定向必须禁跟随 |
| 不做 | 共享账号、绕过计费、代理转发 |

## 3. 三端定位

### 3.1 CLI + Agent Skill（linux / darwin；已定）

- **使用者**：agent（人只是间接受益）。
- **形态 / 能力**：一组可组合子命令，配一份 skill 说明「什么问题跑哪条命令、输出怎么读、失败怎么办」；本期支持 linux / darwin（源码构建 + 预编译产物），windows 为后续计划。Release 提供 `kemaolife_<版本>_darwin_amd64.tar.gz`（Intel Mac / x86_64）与 `kemaolife_<版本>_darwin_arm64.tar.gz`（Apple Silicon / M1 及以后）两个 macOS CLI 预编译包；文件名里的 `darwin` 即 macOS，与仓库 `GOOS=darwin` 口径一致；包内含 `kemaolife` / `LICENSE` / `INSTALL.txt`，与 Linux 包同构。**macOS CLI 未经过实机测试**：仓库无 macOS 真机，darwin amd64 / arm64 仅交叉编译 + 静态审查 + 自动化单测通过，**未在真实 Mac 上运行**；真实终端 `TIOCGETA`/`TIOCSETA` 回显控制与恢复、Gatekeeper `com.apple.quarantine` 与 `xattr -d`、系统根证书链下 HTTPS、`time.Local` 本地时区、Apple Silicon arm64 首次执行不被拦截五项均未实机确认，按试验性支持使用。
- **为什么是 CLI**：agent 不需要 GUI；`stdout` 输出 JSON、`stderr` 输出诊断、用退出码表达错误，是最稳定的机器接口。
- **能力**：单二进制 `kemaolife` + 子命令；`--version` / `--help` / 配置（学号 + 教务密码，学校代码内置默认可覆盖）/ 课表四维度（默认当日）/ 一次返回电费余额与用量。学校代码属学校事实，内置默认值可入仓并支持覆盖，但不得写成 `internal/core` 包级常量。
- **签名、公证与首次运行**：macOS 二进制由 Linux CI 交叉编译，**未经 Apple Developer ID 签名、未经 Apple 公证（notarization）**：无 Apple 付费账号证书，不做公证；arm64 二进制带 Go 链接器自动生成的 ad-hoc 代码签名（Apple Silicon 要求），**这不等于 Apple 签名**。浏览器下载解压后二进制可能带 `com.apple.quarantine`，首次运行被 Gatekeeper 拦截，需手动执行 `xattr -d com.apple.quarantine <解压后的 kemaolife>`（或 `xattr -r -d com.apple.quarantine <目录>`）后再运行。
- **凭据与缓存**：macOS 与 Linux 同口径，凭据仍为 `~/.config/kemaolife/config.json`（目录 `0700` / 文件 `0600` / 原子写，XDG 优先）与 `~/.cache/kemaolife/`，不引 Keychain 与第三方依赖。
- **明确不做**：GUI、常驻、定时提醒、区段查询、校园网状态查询与凭据存储；仍不做 Developer ID 签名 / 公证 / Keychain / 第三方依赖、不宣称 macOS 已实机验证。

### 3.2 Windows · 原生托盘常驻（已定）

- **使用者**：人。
- **形态**：`kemaolife-agent.exe` 常驻系统托盘 + 原生设置窗口 + 通知渠道（D4 已定稿：系统通知为主、托盘状态为辅；当前由托盘 `NIF_INFO` 承载，Windows 按版本呈现气泡 / toast 样式）；**开机登录时自启一次**（可关，设置保存后写入自启项），不做保活、不做守护，被退出或杀掉后不重启。
- **为什么是常驻**：Windows 自启动成本低，能长期驻留并主动推送；这是它相对 Android 的结构性优势。
- **能力**：电费轮询（默认 4 小时，可自定义，≥ 600s 硬下限）→ 阈值提醒 → 可用天数估算；校园网状态可查，手动 / 自动二选一（默认手动）；托盘右键显示认证状态与剩余电费，手动模式提供「登录校园网 / 下线 / 重登」，自动模式省略前两项、保留「重登」；两种模式都有「立即探测校园网 / 立即查询电费 / 设置… / 退出」。
- **课表**：不做主界面（桌面价值低）。
- **明确不做**：浏览器内核、多账号、云端同步。

### 3.3 Android · 原生 App（已定）

- **使用者**：人。
- **形态**：Kotlin + Compose 原生 UI，底栏三个 tab（课表 / 更多 / 设置）；打开即用，不申请自启动、不做后台定时。
- **为什么放弃后台**：电池优化、厂商冻结、后台被杀的成本远大于收益；课表数据按需刷新即可，不做后台也能好用。
- **能力**：**缓存优先**——首帧由 ViewModel 同步读 Kotlin 侧课表展示镜像与电费缓存立即渲染（不等门面 `Init`），`Init` 后由 `CacheOnly` 回读 Go 快照校正；每次打开在门面 `Init` 就绪、凭据已填且无同链路在途请求时，发起一次 `timetable.sync`、一次电费查询与一次必要的校园网判态（不受「最小查询间隔」约束），成功立即覆盖界面；课表失败沿用旧缓存、置 UI 离线标记并保留 `syncedAt`，不阻塞展示、不改写信封 `stale`，电费失败沿用其缓存。课表与电费各有独立「最小查询间隔」：均默认 5 分钟、下限 1 分钟、上限 1440 分钟（1 天），越界值钳制到合法边界并提示；切回课表 tab / 进入更多 tab 等非打开自动触发按各自间隔节流，从后台回到前台仍算打开；手动 `刷新` / `测试` 不受节流；切周只读缓存。tab1 单页周视图：头部固定今天日期、周次弹窗切周 / 返回当前周、右上角 `导出课表` / `刷新`，星期日期行与 12 小节 × 7 天网格同页放进横向翻页容器（跟手拖动、松手吸附、邻周预取、可选 `lastWeek` 作边界）；`导出课表` 把整学期课节导出为 WakeUp 课程表 CSV（只读本机快照、0 请求、SAF 落盘，格式见 [002 §3.1.1](002-功能规格.md#311-课表导出现wakeup-课程表-csv)）。tab2 当天课表概览 + 电费（余额 / 数据截至 / 用量，`刷新`）+ 校园网三态、手动「登录 / 下线 / 重登」与默认折叠的五项接入详情；`测试` 只在设置页。tab3 多级页面：总览 → **教务**（学号 + 密码 + 查询间隔）/ **电费**（继承教务信息开关 / 独立学号 / 学校代码 / 查询间隔）/ **校园网**（独立凭据 + 仅 WiFi 下探测开关，默认开；非 WiFi 不发任何 `campusnet.*` 请求）/ **外观**（跟随系统 / 浅色 / 深色，Android 12+ 莫奈动态取色、AOSP ThemePicker 的 8 个基础色预设与 AMOLED 纯黑偏好，偏好本机持久化；AMOLED 开关可随时设置，仅深色界面应用纯黑背景）/ **关于**（版本、设备 / Android、GitHub 与 MIT 许可）；二级页按系统返回键直接回总览。
- **明确不做**：后台定时、电费提醒、自动认证、浏览器内核。

> 三端不是同一应用的三套皮肤：**CLI 被问、Windows 主动说、Android 随手看**。差异集中在触发器、呈现与平台能力，业务逻辑一份。

## 5. 硬性设计约束

1. **原生 UI**：Windows / Android 不用 WebView / CEF / Wails / PWA；复用层只负责数据。
2. **刷新优先、离线兜底（课表，CLI）**：CLI 查询走 `RefreshFirst`，先尝试刷新；网络失败必须回落旧快照并标 `stale:true`，不得阻塞读取，也不得把旧数据冒充新数据。Android 为缓存优先：查询走 `CacheOnly`（0 请求、信封 `stale` 恒 `false`），联网刷新是独立的 `timetable.sync`；打开 App 先展示缓存再按就绪状态尝试同步，失败沿用旧缓存并置 UI 离线标记，不阻塞展示、不改写信封 `stale`。
3. **不静默降级**：接口失败要明确报错并标注数据时间，不能用旧数据冒充新数据。
4. **本机缓存最小化**：Android 的 Kotlin 侧课表展示镜像与电费缓存只写 UI 必需字段，不含 Cookie / 凭据 / 学号 / `roomName` / `roomVerify`；`allowBackup=false` 且 Android 12+ 的 `dataExtractionRules` 排除全部私有数据。凭据身份变更时清两类缓存并让 Go 删除旧快照。
5. **导出只读快照**：课表 CSV 导出走 `CacheOnly`（0 请求），经系统文件选择器落到用户选定位置，不申请存储权限；导出弹层必须展示快照同步时间，不把快照当实时数据。
6. **可注入时钟**：周次、学期边界、告警去重必须能在单测里指定时间，禁止在 `core` 直接调 `time.Now()`。
7. **占位符原则**：文档、示例、测试固件里的学号 / 姓名 / 房间号 / 凭据一律为占位值。
8. **频率自律**：Windows 托盘电费轮询 ≥ 600 秒/次（设置窗口默认 4 小时、低于 600 秒钳制到 600 秒并提示；该硬下限仅适用于 Windows 轮询）；电费查询连续失败指数退避；校园网判态轮询 ≥ 30 秒/次且失败不退避（探测失败属 `offline` 正常态）。Android 课表与电费各有独立「最小查询间隔」：均默认 5 分钟、下限 1 分钟、上限 1440 分钟（1 天），低于 1 分钟钳制到 1 分钟并提示，无 600 秒硬下限；打开 App 是特殊自动触发，不受间隔约束，查询课表与电费各一次；切回课表 tab / 进入更多 tab 等非打开自动触发按间隔节流，从后台回到前台仍算打开；**手动查询（`刷新` / `测试`）不受该约束**。

## 8. 风险

| 风险 | 应对 |
|---|---|
| 电费接口无鉴权，滥用即违法 | 只查本人；不做批量与公开服务 |
| 个人信息泄露 | 占位符文档、日志脱敏、凭据加密 |
| 电表数据延迟被误读为实时 | CLI 输出、告警通知、Android 电费页均带数据截止时间（Windows 托盘只给当前值） |
| 教务 / 电费网关加签名或改字段 | `core` 单点修改；失败明确报错 |
| CAS 会话失效仍返回 200 | 判响应内容而非状态码 |
| 教务 aic 服务器无 IPv6 监听却有 AAAA 解析 | `HTTPDoer` 内强制 `tcp4`，禁用 v6 而非优选；否则每次请求白等约 10s 超时 |
| 校园网自签证书 | 仅对 Portal HTTPS 客户端跳过校验（探测地址是 HTTP 明文，不涉及证书），不全局关闭 TLS |
| 学校代码因校而异 | 配置项，不硬编码为通用常量 |
| `gomobile` 非官方正式支持 | 先做 M0.5 spike，链路通了再写 UI |
